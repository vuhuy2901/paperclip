# Operations

The API is stateless apart from the database and artifact volume. `worker` claims queued runs and records ordered events. Cancellation uses guarded transitions, a run-status monitor, and runner/gateway process termination; the run keeps its collected evidence and releases its lease. Back up the PostgreSQL metadata, `data/artifacts`, and managed repository/worktree volume together.

Compose runs Core/Worker on PostgreSQL and the local deterministic runner by default. On Windows, run `python scripts/enable_codex_demo.py` after `docker compose up -d --build`; it checks the host Codex CLI login, starts the gateway if needed, and configures all eight Core roles with scoped real Codex execution. The host's existing ChatGPT Codex login is used; no OpenAI API key is copied into Compose or the repository. `codex-gateway` maps only the workspace root. Paperclip runs `local_trusted` on localhost and its adapter verifies a real read-only Codex request before agents become ready. The review UI uses the Core service token in this development deployment. A production deployment still needs a real secret manager, board/PO session, task-container hardening, resource limits, backup restore drills, and a configured model budget.
